When we were told we had to build a game using C# and Windows Forms 
as part of our Object Oriented Programming course, my first reaction 
was pure disbelief. A game. We had to build an actual game. I had 
never touched C# in my life before this. I had never used Windows 
Forms. And yet here we were — assigned to create something that 
actually worked, actually ran, and actually felt like a game.

I decided to build a car game. Completely alone. No group, no partner 
— just me, my laptop, and a lot of determination. Looking back now, 
working alone was both the hardest and the most rewarding decision I 
made. Every problem that came up was mine to solve. Every breakthrough 
was mine to celebrate.

C# felt very different from Python. Python had been my first 
programming language and I had gotten comfortable with its simple, 
readable syntax. C# was stricter, more structured, more demanding. 
Everything had to be declared properly. Types mattered. Structure 
mattered. It took time to adjust but slowly the language started 
making sense.

Windows Forms was a whole new world. Designing the interface — placing 
buttons, arranging elements on the screen, making everything look 
right — was more challenging than I expected. Getting buttons to sit 
exactly where I wanted them, making the layout feel like an actual 
game screen, arranging all the visual elements properly — it sounds 
simple but it took hours of tweaking and adjusting. Every small 
detail required attention.

The virus element of the game was one of the most interesting parts 
to build. Creating something that moved, that posed a challenge to 
the player, that had its own behavior within the game — that required 
real logic and real coding. Making it work correctly, making it feel 
like an actual obstacle in the game, was deeply satisfying once it 
finally functioned the way I intended.

Throughout the entire project, the four pillars of OOP were my 
foundation. Encapsulation, Inheritance, Polymorphism, and Abstraction 
— concepts we had learned in theory suddenly had real, practical 
meaning. Encapsulation kept my data safe and organized within classes. 
Inheritance allowed me to build on existing code without rewriting 
everything. Polymorphism gave my objects the flexibility to behave 
differently in different situations. Abstraction kept the complexity 
hidden and the code clean. Using all four pillars in a real project 
made me understand them in a way no textbook ever could.

When the game finally ran — when the car moved, when the virus 
appeared, when everything worked together as one complete thing — 
the feeling was unlike anything I had experienced before. I had built 
something. Something real. Something that worked. Something I had 
created completely on my own from scratch.

OOP taught me that programming is not just about writing code — it 
is about thinking in a structured, organized way. And building that 
car game taught me that the best way to truly understand any concept 
is to build something with it.
